Next.js / App Router
01What is the difference between Server Components and Client Components in the App Router? When would you use each?
Core▼
Key Points

Server Components (RSC) render on the server, have no JS bundle cost on the client, can directly access databases/secrets, and cannot use hooks or browser APIs.

Client Components (marked with "use client") run in the browser — use them for interactivity, event handlers, useState, useEffect, browser APIs.

Rule of thumb: Default to Server Components. Push interactivity to leaf components. This keeps the client bundle small and enables streaming.

// app/page.tsx — Server Component (default)
async function Page() {
  const data = await db.query(...)  // Direct DB access ✓
  return <ClientWidget data={data} />
}

// components/ClientWidget.tsx
"use client"
export function ClientWidget({ data }) {
  const [open, setOpen] = useState(false)
  ...
}
02Explain Server Actions. How do they replace traditional API routes for mutations?
Important▼
Key Points

Server Actions are async functions marked with "use server". They run exclusively on the server but can be called directly from Client Components — Next.js handles the HTTP layer automatically.

They replace boilerplate fetch('/api/...') calls, come with built-in CSRF protection, integrate with revalidatePath/revalidateTag for cache invalidation, and work with React's useTransition for pending states.

"use server"
export async function updateUser(id: string, data: FormData) {
  const name = data.get('name')
  await db.users.update({ where: { id }, data: { name } })
  revalidatePath('/users')
}
03What are the caching layers in Next.js 14+? How do you opt out or revalidate each?
Deep▼
Key Points

Next.js has 4 caches: Request Memoization (per-request, auto deduplicates fetch), Data Cache (persistent, configured via fetch options), Full Route Cache (static HTML/RSC payload at build), Router Cache (client-side, prefetched segments).

Opt out: fetch(url, { cache: 'no-store' }) or export const dynamic = 'force-dynamic'. Revalidate: revalidatePath(), revalidateTag(), or fetch(url, { next: { revalidate: 60 } }).

04How does Streaming and Suspense work with the App Router for improving perceived performance?
Important▼
Key Points

Next.js streams HTML progressively using React Suspense. The server sends an initial shell immediately, then streams each suspended segment as it resolves. Wrap slow data-fetching components in <Suspense fallback={...}>.

Use loading.tsx for route-level skeleton UIs. Use error.tsx for error boundaries. The key metric win: Time to First Byte (TTFB) and Largest Contentful Paint (LCP) improve because the shell arrives instantly.

05What is the Edge Runtime in Next.js and when should you use Middleware?
Important▼
Key Points

Edge Runtime is a lightweight V8 runtime deployed at CDN nodes (not Node.js full runtime). It has no native Node modules, limited APIs, but starts in <1ms. Use for: auth checks, redirects, A/B testing, locale detection, geolocation-based routing.

Middleware (middleware.ts at project root) runs on every request before cache lookup — ideal for auth guards, request rewrites, header manipulation. Keep it fast and stateless.

06How do you handle dynamic vs static rendering in App Router? Explain generateStaticParams.
Core▼
Key Points

By default, routes are statically rendered at build time if they don't use dynamic functions (cookies(), headers(), searchParams). generateStaticParams() pre-generates dynamic route segments (like [slug]) at build time for SSG.

// app/blog/[slug]/page.tsx
export async function generateStaticParams() {
  const posts = await getPosts()
  return posts.map(p => ({ slug: p.slug }))
}
Supabase
07Explain Row Level Security (RLS) in Supabase. How would you secure a multi-tenant app?
Deep▼
Key Points

RLS is PostgreSQL's policy-based access control. When enabled on a table, ALL queries are denied by default unless a policy permits them. Supabase uses the JWT's sub claim (user ID) via auth.uid().

-- Users can only read their own rows
CREATE POLICY "user_isolation" ON documents
  FOR SELECT USING (auth.uid() = user_id);

-- Org-based multi-tenancy
CREATE POLICY "org_access" ON documents
  FOR ALL USING (
    org_id IN (
      SELECT org_id FROM memberships WHERE user_id = auth.uid()
    )
  );

Always enable RLS + set policies before going to production. Test with the Supabase policy editor using different JWT tokens.

08How do you use Supabase Auth with Next.js App Router, including server-side session handling?
Important▼
Key Points

Use @supabase/ssr package (not the old Auth Helpers). Create two Supabase clients: one for server components/actions using createServerClient with cookie adapters, and one for client components using createBrowserClient.

Use Next.js Middleware to refresh sessions on every request so Server Components always get fresh auth state. The middleware calls supabase.auth.getUser() which validates the JWT against Supabase's server.

09What are Supabase Edge Functions? When would you use them over Next.js API routes?
Context▼
Key Points

Edge Functions are Deno-based serverless functions deployed globally alongside your database. Use them for: webhooks that need DB access without network latency, Supabase-specific triggers (e.g., post-auth hooks), or logic that shouldn't be in your Next.js app (e.g., third-party integrations, sending emails via Resend).

Prefer Next.js API routes / Server Actions for app-logic. Use Supabase Edge Functions for database-adjacent automation and webhook receivers.

10How do you handle database schema migrations in Supabase for a production app?
Practical▼
Key Points

Use the Supabase CLI with supabase db diff and supabase migration new. Store migration files in version control. Use supabase db push for staging, and CI/CD pipelines for production. Never edit production DB directly without a migration file.

For zero-downtime: add columns as nullable first, backfill data, then add NOT NULL constraints. Use separate migrations for DDL and DML changes.

Inngest
11What is Inngest and how does it differ from a traditional job queue like BullMQ or Celery?
Core▼
Key Points

Inngest is a durable execution platform — it orchestrates serverless functions with built-in retries, steps, delays, and event-driven triggers without requiring a separate Redis/queue server.

Key difference: Inngest functions can pause mid-execution (step.waitForEvent()), retry individual steps (not the whole function), and run on serverless infra. BullMQ requires Redis and doesn't natively handle serverless cold starts or mid-function pausing.

12How do you define an Inngest function with multiple steps? Why are steps important?
Deep▼
Key Points

Steps provide durable execution: each step's result is persisted. If the function fails mid-way, Inngest retries from the last completed step, not from the beginning. This prevents duplicate work.

inngest.createFunction(
  { id: "send-onboarding" },
  { event: "user.created" },
  async ({ event, step }) => {
    const user = await step.run("fetch-user", async () => {
      return db.users.findById(event.data.userId)
    })
    await step.sleep("wait-1-day", "1d")
    await step.run("send-email", async () => {
      await sendEmail(user.email, "onboarding")
    })
  }
)
13How do you integrate Inngest with a Next.js App Router project?
Practical▼
Key Points

Create a Route Handler at app/api/inngest/route.ts that exports GET, POST, PUT handlers using serve() from inngest/next. Register all your functions there. Inngest's cloud calls this endpoint to execute functions.

import { serve } from "inngest/next"
import { inngest } from "@/lib/inngest"
import { sendOnboarding } from "@/inngest/functions"

export const { GET, POST, PUT } = serve({
  client: inngest,
  functions: [sendOnboarding]
})
14Describe a real-world scenario where you'd use Inngest over a simple setTimeout or API call.
Scenario▼
Key Points

Good examples: (1) Trial expiry emails — send a series of emails at days 1, 7, 14 without cron jobs. (2) AI pipeline — trigger after file upload, process in steps (extract → embed → index → notify), each step retriable. (3) Webhook fanout — receive webhook, fan out to 100 subscribers with per-subscriber retry logic.

The key value: long-running processes that can't block an HTTP response, need reliability, and benefit from observability (Inngest dashboard shows every run).

Vercel / DevOps
15How do you use Vercel Preview Environments in a team workflow? What are their limitations?
Practical▼
Key Points

Every PR/branch gets an automatic Preview deployment with a unique URL. Use cases: stakeholder review, QA testing, integration testing against a staging Supabase project. Use VERCEL_ENV env var to switch configs per environment.

Limitations: Preview envs share limits with production (function timeout, bandwidth), environment variables must be set per-environment scope in Vercel dashboard, and DB connections can get exhausted if many previews run simultaneously — use Supabase connection pooling (pgBouncer).

16What is Vercel Edge Config and when would you use it over environment variables?
Deep▼
Key Points

Edge Config is an ultra-low-latency key-value store (reads in ~1ms globally) that can be updated without redeployment. Ideal for: feature flags, A/B test variants, maintenance mode toggles, allowed IP lists — anything that needs to change fast without a full deploy.

Env variables are baked into the build; Edge Config is read at runtime from Vercel's edge network. Trade-off: Edge Config has size limits (~512KB) and is only readable (not writable) from your app at runtime.

17How do you optimize Core Web Vitals (LCP, CLS, INP) in a Next.js application?
Performance▼
Key Points

LCP: Use next/image with priority on hero images, serve from edge CDN, use font-display: optional for custom fonts. Prefer static rendering where possible.

CLS: Always set explicit width/height on images (next/image handles this), reserve space for async-loaded content, avoid dynamically injected content above the fold.

INP (Interaction to Next Paint): Move heavy work to server components, use useTransition for non-urgent state updates, code-split large client bundles with dynamic() imports.

TypeScript & Patterns
18How do you type Server Actions and handle validation with Zod in Next.js?
Practical▼
Key Points

Use Zod for input validation inside Server Actions. Return typed results for the client to consume. Use useFormState (React 19: useActionState) to display server-side errors.

const schema = z.object({ email: z.string().email() })
export async function subscribe(prevState: any, fd: FormData) {
  const result = schema.safeParse({ email: fd.get('email') })
  if (!result.success)
    return { error: result.error.flatten().fieldErrors }
  // ... proceed with valid data
  return { success: true }
}
19Explain the difference between useCallback, useMemo, and memo in React. When are they actually needed?
React▼
Key Points

memo wraps a component to skip re-renders if props haven't changed. useMemo memoizes a computed value. useCallback memoizes a function reference (prevents child re-renders when passing callbacks).

When actually needed: Only when you've measured a performance problem. Premature memoization adds cognitive overhead and can backfire. Most useful for: expensive calculations, stable callbacks passed to memoized children, or reference equality checks in effects/selectors.

20How do you design a scalable folder structure for a large Next.js App Router project?
Architecture▼
Key Points

Feature-based co-location within app/ for routes. Shared logic in lib/ (DB clients, utils), components/ (shared UI), hooks/, types/. Use _ prefix to exclude folders from routing (e.g., app/_components/).

app/
  (auth)/login/      # Route group, no URL prefix
  dashboard/
    _components/     # Co-located, not a route
    page.tsx
lib/
  supabase/          # server.ts, client.ts, middleware.ts
  inngest/           # client.ts, functions/
components/ui/       # Shared design system
inngest/functions/   # All Inngest functions

Quick-Fire / Curveballs
24What's the difference between layout.tsx and template.tsx in App Router?
Quick▼
Key Points

layout.tsx persists across navigations (state is preserved, not re-mounted). template.tsx creates a new instance on every navigation (state resets, effects re-run). Use templates for: enter/exit animations, page-specific analytics tracking, useEffect that should re-fire on route change.

25How do you prevent SQL injection in Supabase/PostgreSQL queries?
Quick▼
Key Points

Supabase's JS client uses parameterized queries automatically — never string-concatenate user input into queries. For raw SQL (e.g., in Edge Functions or RPC), use parameterized queries ($1, $2 placeholders). Never use .rpc() with untrusted string interpolation.

26What's a "N+1 query" problem and how do you fix it in a Supabase app?
Quick▼
Key Points

N+1: fetching a list (1 query) then firing a query per item (N queries) — e.g., get 50 posts, then fetch author for each. Fix: use Supabase's select('*, author:profiles(*)') to JOIN in one query, or use PostgreSQL views/functions to batch data. In React, use Promise.all for parallel fetches when joins aren't possible.

27What is use cache directive in Next.js 15 and how does it change the caching model?
Cutting-Edge▼
Key Points

Next.js 15 introduced the "use cache" directive (experimental) as a more granular, explicit caching API. You can add it to a function, component, or entire file to mark its output as cacheable. Unlike the old implicit fetch caching (which was controversial and removed in Next.js 15 by default), use cache is opt-in and composable with cacheLife() and cacheTag() for fine-grained control.
